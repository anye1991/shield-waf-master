# 架构文档（Architecture / High-level Design）

> 对应 OpenSSF 准则 `documentation_architecture`。描述 **YSL语枢-盾甲WAF** 的高层设计、模块边界与请求处理流水线。核心代码 `core/`、`ai/` 以加密形式分发（php-beast 定制扩展），设计原则与论文《语枢 YSL-1》一致。

## 1. 部署形态

```
站点之外（本仓库）                       站点内
├── shield-waf.php   ◀── .user.ini ──▶  站点 PHP 文件
├── core/  ai/  ext/                    （auto_prepend_file 每请求前置）
├── var/   logs/
└── install.php ──写入──▶ .user.ini（auto_prepend_file=<…>/shield-waf.php）
```

- **嵌入式 WAF**：非反向代理网关，靠 `auto_prepend_file` 在每个 PHP 请求前生效，**不碰业务代码**。
- `install.php --site=<docroot>` 只写 `.user.ini`，卸载即删该行。

### 1.1 形态边界：为什么不分发 Docker 镜像

| 形态 | 流量路径 | WAF 位置 | 容器化 |
|---|---|---|---|
| 进程内嵌（本版） | 请求 → 业务 PHP-FPM | `auto_prepend_file` 前置执行 | ❌ 无意义：独立容器不处于业务进程内，收不到请求 |
| 反向代理（商业版） | 请求 → 代理 :443 → 源站 | 独立进程置于链路中 | ✅ 天然适配 |

- 旧版 `docker-compose.yml`（v3.1.0）把 nginx + php + WAF 打成镜像并映射 `8080:80`，只能保护「运行在该容器内」的站点，属演示环境，对真实站点不构成防护。
- 若需容器化本版，正确做法是**并入业务镜像**而非单开容器：
  1. 构建期 `COPY . /opt/shield-waf`（位于站点 docroot 之外）；
  2. 向站点 `.user.ini` 写入 `auto_prepend_file=/opt/shield-waf/shield-waf.php`；
  3. 卸载即删除该行，业务镜像其余部分不受影响。
- 选型判断：需要独立进程、多站点集中接管、TLS 终止或集群同步时，应选反向代理形态；本版定位是单站点零侵入。

## 2. 模块划分

| 模块 | 文件 | 职责 | 可见性 |
|---|---|---|---|
| 前置接入层 | `shield-waf.php` | 每请求入口：加载运行时配置、蜜罐判定、限流、分发至内核 | 开放 |
| 运行时配置 | `config.php` / `runtime.php` | 配置契约、运行时状态读写（`var/data/runtime.json`） | 开放 |
| **YSL-1 内核** | `core/YslWaf.php` `core/YslEngine.php` | 语义分析四级流水线、证据证书产出 | 加密 |
| **AI 自学习** | `ai/*`（12 文件） | 朴素贝叶斯 / Robinson-Fisher / SimHash 指纹，运行时持续学习去歧义 | 加密 |
| QPS 限流熔断 | `qps.php` | 滑动窗口计数 → 429 限流 / 502 熔断，阈值实时可调 | 开放 |
| 文件 DNA 防篡改 | `dna.php` | 站点文件指纹基线，独立 CLI 守护；高置信后门手术/隔离 | 开放 |
| 响应页 | `pages.php` | 403/429/502 等美化响应页（全中文） | 开放 |
| 控制台 / 大屏 | `console.php` `screen.php` `control.php` | 零 JS 服务端渲染；40 项功能逐项可控 | 开放 |
| 展示层本地化 | `i18n.php` | 状态/原因/文案统一中文 | 开放 |
| 功能开关 | `features.php` | 功能矩阵与白名单 | 开放 |
| 安装器 | `install.php` | 安装 / `--check` 自检 / `--site` 接入 / 卸载 | 开放 |
| 构建器 | `build.php` | 用 php-beast 扩展把明文源加密为 `core/`、`ai/` | 开放 |
| 扩展 | `ext/beast-8.1.so` `ext/beast.ini` | 运行时透明解密加密文件 | 二进制 |
| 监控存储 | `var/`、`logs/` | C2 监控模块数据（依赖 `pdo_sqlite`，未装则降级，主检测不受影响） | 运行时 |

## 3. 请求处理流水线（YSL-1 四级，确定性执行）

```
HTTP 请求
   │
   ▼
① DFA 预筛 ──▶ 快速命中/排除，缩小待分析片段集
   │
   ▼
② 图模式匹配 ──▶ 在 USG 超图上做类型化模式匹配；
   │              同一段文本可同时是 SQL 片段与 HTML 文本（多假设并存）
   ▼
③ 抽象解释不动点 ──▶ 对假设集求单调不动点，无回溯、可证终止、时延有静态上界
   │
   ▼
④ 证据证书 ──▶ 四值证据域（⊥·S·M·T）合成判定：
                阻断附带「子图 + 命中规则 + 归一化轨迹」可机器复核证书
```

**设计原则**：
- **不猜单一上下文**：保留一组上下文假设（部分解析森林），判定在假设集上单调、可合成、可复核——AST 只是退化特例。
- **四值证据域替代布尔**：让「不确定」可见；而非一刀切放行/拦截。
- **无模型调用**：请求路径上无 LLM/网络调用；LLM 仅作离线规则编译器 / 反例生成器，产物须过类型检查、差分测试、反例搜索三道闸。

## 4. AI 自学习闭环（离线产物进请求路径）

1. 运行期采集判定样本（放行/阻断 + 证据证书摘要）。
2. 离线/低频更新：朴素贝叶斯先验、Robinson-Fisher 聚合、SimHash 近重复指纹。
3. 更新产物经置信阈值后加载进内核，用于**去歧义**（降低误报），不改变四级流水线的确定性。

## 5. 关键安全设计决策

| 决策 | 理由 |
|---|---|
| 站点外安装（`.user.ini` 指向） | 即使站点目录被完全攻陷，WAF 本体不被覆盖 |
| 蜜罐默认停用 + 四道闸 | 避免误伤与自身成为攻击面；到期自动回退 |
| 零 JS 控制台 | 严格 CSP / 离线环境可用；无 XSS 注入面 |
| 加密核心（php-beast） | 保护内核知识产权；**非安全边界**——安全依赖 YSL-1 检测语义而非加密保密性 |
| `core/` 与 `ai/` 与开放层解耦 | 开放层可审计、加密层可替换升级，契约由 `config.php` 固定 |

## 6. 外部依赖

- 运行时：**PHP ≥ 8.1**；`pdo_sqlite`（可选，仅 C2 监控，缺失优雅降级）
- 扩展：随附 `ext/beast-8.1.so`（php-beast 定制版，密钥固化）
- 构建期：php-beast 扩展 + PHP CLI（仅作者构建加密产物时需要）

> 机器可读依赖清单见 `composer.json`。
