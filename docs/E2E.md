# 加密发行版 · 容器化验收报告

> 一句话结论：**加密后的 core/ 与 ai/ 在干净的 PHP 8.1 环境里能正常解密运行，拦截判定、控制台、大屏、限流、降级提示全部符合预期，2376 条对抗样本**全部拦截（漏放 0）**。

本报告只描述**加密发行版在真实运行环境中的表现**，不涉及加密实现细节。所有数字都可由仓库内脚本复现：

```bash
bash tools/e2e_encrypted.sh        # 需要本机已装 Docker
```

脚本会在 `php:8.1-cli` 干净容器里，按 README 的部署步骤装好随附扩展，把仓库挂到 `/app` 后逐项验收。全程不修改仓库文件。

## 四、极限对抗结果

共 2376 条真实 HTTP 投放样本（12 类攻击 × 12 种逃逸变异 × 3 个投放面）：

| 类别 | 样本 | 漏放 | 拦截率 |
|---|---|---|---|
| SQL 注入 | 288 | 0 | 100% |
| XSS | 216 | 0 | 100% |
| 路径穿越 | 216 | 0 | 100% |
| 命令注入 | 360 | 0 | 100% |
| 服务端模板注入 | 216 | 0 | 100% |
| NoSQL 注入 | 180 | 0 | 100% |
| XXE | 144 | 0 | 100% |
| 反序列化 | 180 | 0 | 100% |
| SSRF | 168 | 0 | 100% |
| 文件包含 | 216 | 0 | 100% |
| CRLF 注入 | 96 | 0 | 100% |
| LDAP 注入 | 96 | 0 | 100% |
| **合计** | **2376** | **0** | **100%** |

**这一轮补上了什么**：上一版验收在反序列化类漏放 6 条，全部是「序列化 payload 先 base64 编码，再整块大写 / 小写 / 大小写翻转」的组合。base64 区分大小写，变形后原样解码只得乱码，靠「解码后比对」的路径一律失效；但 base64 每 3 字节编码 4 字符，明文前 6 字节与 base64 前 8 字符是一一对应的固定映射，因此改用**大小写无关的前缀指纹**在不解码的前提下识别（裸 base64、≥16 字符、8 字符精确前缀，门槛收紧到正常人不会误触）。现已 **6/6 全部拦截**，且正常长 base64 文本、中文参数仍照常放行。

## 五、性能（单进程内置服务器）

| 指标 | 数值 |
|---|---|
| 正常请求 P50 | 4.4 ms |
| 正常请求 P95 | 6.2 ms |
| 正常请求最大 | 10.5 ms |
| 拦截请求 | 4.4 ~ 7.5 ms |
| 控制台 | 4.4 ms |
| 态势大屏首屏 | 384 ms |
| 大屏 JSON | 371 ms |

说明：延迟含本机回环网络往返，且运行在 `php -S` 单进程模式下，未开 opcache、未做任何调优。生产环境走 PHP-FPM + opcache，实际会更快。

控制台 4.4 ms、大屏 370+ ms 的差距来自渲染量：大屏一次要聚合审计链、时间窗、熔断状态、AI 信号等多个数据源并渲染整页 HTML，属预期开销；大屏是人工查看页面，不在业务请求路径上。

## 六、限流与降级

**限流（默认 80 QPS/单 IP 软限）**：单 IP 突发 140 次，0.37 秒内 79 次返回 200，之后 61 次返回 429。阈值准确，无越限放行。

**observe 观察模式**：注入请求照常放行（200），审计日志照常落盘（14 个状态文件）。可放心先观察再拦。

**缺扩展（最常见部署失误）**：

| 场景 | 表现 |
|---|---|
| 未装扩展先接站 | 返回 **503**，页面写明「安全模块暂时不可用」，不再白屏/乱码 |
| `install.php --check` | 直接 FAIL 并中止，不写入任何配置 |

## 七、上一版发现的两处问题（本版已修）

| 问题 | 处理 |
|---|---|
| 反序列化 payload 做 base64 后再破坏大小写，6 条样本被放行 | 归一化层补 `base64_case_flip`（flip / lower / upper 三变体），并新增「大小写无关的序列化前缀指纹」确定性判定 → **2376/2376 全部拦截** |
| 干净请求偶发一条 `YslArbiter::arbitrate failed (Error)` 错误日志 | 降级路径统一降为 debug 级（`WAF_DEBUG=1` 才落盘），并附带异常消息与位置；仅审计落盘、子系统装配、熔断计数三类仍保留 error → **本次验收日志 0 条噪音** |

> 两条都在内核内部，随内核重新构建一并生效，外壳与部署方式不变。

## 八、如何复现

```bash
# 全量验收（约 1 分半）
bash tools/e2e_encrypted.sh

# 只跑功能向量（需先自行起站点，默认 8080）
php tools/e2e/vectors.php http://127.0.0.1:8080 <控制台密钥>

# 只跑内核判定（不经 HTTP）
php tools/e2e/kernel_check.php /path/to/waf /path/to/logs
```

`tools/e2e/` 下四个文件：

| 文件 | 作用 |
|---|---|
| `inner.sh` | 容器内验收主流程（10 个阶段） |
| `vectors.php` | HTTP 攻击/正常/管理面向量 + 延迟采样 |
| `kernel_check.php` | 直接调用内核，验证「解密 → 解析 → 证据 → 仲裁」链路 |
| `router.php` | 内置服务器路由（让虚拟路由进到 WAF；内置服务器不执行 auto_prepend，故显式前置加载） |

## 九、验收结论

- **加密发行版可正常交付**：干净环境按 README 部署后，扩展加载、内核解密、全部功能可用。
- **拦截能力达标**：2376 条对抗样本**全部拦截**（漏放 0），含上版漏放的 6 条大小写混淆载荷。
- **误报可控**：正常业务请求（含中文路径、中文参数）全部放行。
- **失败姿态安全**：缺扩展、内核异常等场景均为显式 503，不会静默放行。
- **性能可接受**：单进程无优化下 P50 5.2 ms / P95 6.1 ms。

**上线前建议**：生产环境先用 `WAF_MODE=observe` 跑 3~7 天，看审计日志里的误报再切 `enforce`。
