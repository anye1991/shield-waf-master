# 加密发行版 · 容器化验收报告

> 一句话结论：**加密后的 core/ 与 ai/ 在干净的 PHP 8.1 环境里能正常解密运行，拦截判定、控制台、大屏、限流、降级提示全部符合预期，2376 条对抗样本漏放 6 条（0.25%）。**

本报告只描述**加密发行版在真实运行环境中的表现**，不涉及加密实现细节。所有数字都可由仓库内脚本复现：

```bash
bash tools/e2e_encrypted.sh        # 需要本机已装 Docker
```

脚本会在 `php:8.1-cli` 干净容器里，按 README 的部署步骤装好随附扩展，把仓库挂到 `/app` 后逐项验收。全程不修改仓库文件。

## 四、极限对抗结果

共 2376 条真实 HTTP 投放样本（12 类攻击 × 12 种逃逸变异 × 3 个投放面）：

| 类别 | 样本 | 漏放 | 拦截率 |
|---|---|---|---|
| SQL 注入 | 288 | 0 | 100% |
| XSS | 216 | 0 | 100% |
| 路径穿越 | 216 | 0 | 100% |
| 命令注入 | 360 | 0 | 100% |
| 服务端模板注入 | 216 | 0 | 100% |
| NoSQL 注入 | 180 | 0 | 100% |
| XXE | 144 | 0 | 100% |
| **反序列化** | 180 | **6** | **96.7%** |
| SSRF | 168 | 0 | 100% |
| 文件包含 | 216 | 0 | 100% |
| CRLF 注入 | 96 | 0 | 100% |
| LDAP 注入 | 96 | 0 | 100% |
| **合计** | **2376** | **6** | **99.75%** |

**漏放的 6 条是什么**：全部是「反序列化 payload 先 base64 编码，再做纯大小写翻转」的组合。base64 区分大小写，大小写翻转后这串已不是合法 base64、还原不出原始对象，属于**变异器制造的无效载荷**，落到业务页也不会触发反序列化。真正需要关注的是「deser + base64（原样）」这类仍然可还原的组合，本次全部拦截。

> 结论：反序列化这一类可以补一条「payload 大小写翻转后仍按 base64 尝试解码」的检测，属于可优化项，不是漏洞。

## 五、性能（单进程内置服务器）

| 指标 | 数值 |
|---|---|
| 正常请求 P50 | 4.4 ms |
| 正常请求 P95 | 6.2 ms |
| 正常请求最大 | 10.5 ms |
| 拦截请求 | 4.4 ~ 7.5 ms |
| 控制台 | 4.4 ms |
| 态势大屏首屏 | 384 ms |
| 大屏 JSON | 371 ms |

说明：延迟含本机回环网络往返，且运行在 `php -S` 单进程模式下，未开 opcache、未做任何调优。生产环境走 PHP-FPM + opcache，实际会更快。

控制台 4.4 ms、大屏 370+ ms 的差距来自渲染量：大屏一次要聚合审计链、时间窗、熔断状态、AI 信号等多个数据源并渲染整页 HTML，属预期开销；大屏是人工查看页面，不在业务请求路径上。

## 六、限流与降级

**限流（默认 80 QPS/单 IP 软限）**：单 IP 突发 140 次，0.37 秒内 79 次返回 200，之后 61 次返回 429。阈值准确，无越限放行。

**observe 观察模式**：注入请求照常放行（200），审计日志照常落盘（14 个状态文件）。可放心先观察再拦。

**缺扩展（最常见部署失误）**：

| 场景 | 表现 |
|---|---|
| 未装扩展先接站 | 返回 **503**，页面写明「安全模块暂时不可用」，不再白屏/乱码 |
| `install.php --check` | 直接 FAIL 并中止，不写入任何配置 |

## 七、发现的两个可优化点

1. **反序列化大小写翻转变体**（见第四节）——建议补「大小写翻转后仍尝试 base64 解码」的归一化。
2. **日志噪音**：干净请求偶尔会打一条 `YslArbiter::arbitrate failed (Error)` 到错误日志。这是内核里「某模块缺失 → 降级」路径留下的提示，**不影响判定结果**（本次 8/8 判定全对，攻击全部拦截），但会干扰运维排查。建议下一版内核把该日志降为 debug 级，或补齐缺省实现后不再触发。

> 需要说明：这两条都在加密内核内部，属内核版本问题，无法通过改外壳绕开；下一版内核编译时一并修掉即可。

## 八、如何复现

```bash
# 全量验收（约 1 分半）
bash tools/e2e_encrypted.sh

# 只跑功能向量（需先自行起站点，默认 8080）
php tools/e2e/vectors.php http://127.0.0.1:8080 <控制台密钥>

# 只跑内核判定（不经 HTTP）
php tools/e2e/kernel_check.php /path/to/waf /path/to/logs
```

`tools/e2e/` 下四个文件：

| 文件 | 作用 |
|---|---|
| `inner.sh` | 容器内验收主流程（10 个阶段） |
| `vectors.php` | HTTP 攻击/正常/管理面向量 + 延迟采样 |
| `kernel_check.php` | 直接调用内核，验证「解密 → 解析 → 证据 → 仲裁」链路 |
| `router.php` | 内置服务器路由（让虚拟路由进到 WAF；内置服务器不执行 auto_prepend，故显式前置加载） |

## 九、验收结论

- **加密发行版可正常交付**：干净环境按 README 部署后，扩展加载、内核解密、全部功能可用。
- **拦截能力达标**：2376 条对抗样本拦下 2370 条，漏放的 6 条经分析为无效载荷。
- **误报可控**：正常业务请求（含中文路径、中文参数）全部放行。
- **失败姿态安全**：缺扩展、内核异常等场景均为显式 503，不会静默放行。
- **性能可接受**：单进程无优化下 P95 6.2 ms。

**上线前建议**：生产环境先用 `WAF_MODE=observe` 跑 3~7 天，看审计日志里的误报再切 `enforce`。
