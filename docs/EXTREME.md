# 加密发行版 · 极限测试报告

> 一句话结论：**用超大请求体、深层混淆、多 worker 并发、20s 长稳去打，前后共逼出 5 个真实缺陷（含一个可被任何人触发的 DoS、一个 500 崩溃、一个随运行时间持续退化的性能缺陷），全部已修复；修复后五个阶段全绿，功能回归 21/21 向量、2376 条对抗样本漏放 0，长稳 P50 23ms、吞吐约 1160 req/s。**

本报告是 [docs/E2E.md](E2E.md) 的补充：E2E 验「能不能用」，这份验「往死里打会怎样」。所有数字都可由仓库内脚本复现：

```bash
bash tools/stress_extreme.sh                        # 全套五阶段，需要本机已装 Docker
STRESS_N=1000 STRESS_CC=64 bash tools/stress_extreme.sh   # 加大并发量
STRESS_STAGES="boundary profile" bash tools/stress_extreme.sh  # 只跑指定阶段
```

脚本在干净的 `php:8.1-cli` 容器里按 README 步骤装好随附扩展，把仓库**只读**挂到 `/src`、在 `/app` 副本里跑全部动作，不改动仓库文件。

## 一、测试环境

| 项 | 值 |
|---|---|
| 运行环境 | Docker `php:8.1-cli`（PHP 8.1.34，Debian） |
| 服务 | `php -S` + `PHP_CLI_SERVER_WORKERS=8`（多 worker，专门制造并发） |
| PHP 参数 | `post_max_size=64M`、`max_input_vars=100000`、`memory_limit=512M`、`max_execution_time=0` |
| 部署形态 | 进程内嵌：`auto_prepend_file` 前置加载，业务页零改造 |
| 加密内核 | 仓库 `core/` 19 个 + `ai/` 12 个，随附 `ext/beast-8.1.so` 解密 |
| 客户端 | 纯 PHP `curl_multi` 并发探针（`tools/stress/extreme.php`），不依赖 ab/wrk |
| 状态 | 每阶段前清理限流 / 熔断 / 攻击链 / 时间窗状态，从干净基线开始 |

## 二、五个阶段与判定口径

| 阶段 | 打什么 | 硬性断言 |
|---|---|---|
| `boundary` | 1KB~16MB 请求体、8MB 上限两侧、5000 参数、嵌套深度 70、NUL / 非法 UTF-8 / CRLF、超长 query、长尾夹带攻击 | 不出现 5xx、不超时；良性放行或保守 413；攻击必拦 |
| `evasion` | 11 类载荷 × 15 种变异（多层 URL 编码、全角同形字、HTML 实体、注释拆分、base64 翻转 / 大小写）× 统一投放层 = 165 条 | **有效绕过**必须拦（403/413/429/502） |
| `concurrency` | 600 请求 × 并发 16 / 32 / 64，7 成良性 + 3 成攻击，分散来源 IP | 零 5xx、零连接失败、良性零误拦、攻击零漏放 |
| `soak` | 20s 持续混合流量（并发 32） | 同上，并断言长稳前后段 P50 漂移 ≤50%、日志零噪音 |
| `state` | 400 次突发触发限流/熔断（低阈值配置），并发写状态文件，冷却后探测恢复 | 必须触发 429/502、状态文件仍是合法 JSON、能自行恢复 200 |

口径说明：`evasion` 里 **22 条「b64 全大写 / 全小写」属于不可逆变异**——base64 字符集大小写敏感，整块大写后连攻击者自己的业务端都还原不出原文，不构成真实攻击路径，因此只记录不判失败。其余 **143 条有效绕过**（含可逆的 `b64 flip`）才是硬性验收对象。测试脚本对**所有**向量统一做一次 URL 编码投放，避免空格 / 换行 / 全角字符让 HTTP 客户端直接拒绝 URL 而出现假失败。

## 三、打出来的 5 个真缺陷

| # | 现象 | 严重度 | 根因 |
|---|---|---|---|
| 1 | 64KB / 1MB 良性文本请求 **超时 >20~35s**；8 worker 被几个大请求打满即全站不可用 | 🔴 严重 DoS | `YslNormalizer::calculateEntropy()` 用 `mb_substr($str,$i,1)` 逐字符取，是 O(n²) |
| 2 | 1MB 良性文本直接 **500**，服务日志 `Allowed memory size of 536870912 bytes exhausted` | 🔴 崩溃 | `NaiveBayesClassifier::tokenize()` 对整串做 2/3-gram，1MB → 约 200 万 token，数组扩容申请 256MB |
| 3 | 64KB 填充 + 尾部 `<script>alert(1)</script>` **放行 200** | 🟠 漏放 | `collectParamText()` 只取参数前 4000 字节，确定性硬规则看不到尾部载荷 |
| 4 | `b64 flip` 对 SQL 恒真式 / SSTI / CRLF **漏放 6 条** | 🟠 漏放 | 大小写混淆变体的采纳门槛只认序列化 / 代码执行 / 敏感路径等硬结构 |
| 5 | 并发 64 时 P50 **1.3s**、20s 长稳期间 P50 从 983ms **持续上浮**到 1209ms，吞吐只有 40 req/s | 🔴 性能退化 | `YslAudit::flush()` 每请求全量逐行解码历史日志找链末端 hash（O(n²)），且 8 个 worker 抢同一把 `.audit.lock` 串行等待 |

另外两项属于**测试脚本口径**而非产品缺陷，已修正：控制台未带密钥返回 403 是预期（未授权）；`b64` 全大写/全小写不可逆，不应判失败。

### 长度-耗时曲线（修复前，单请求端到端）

| 文本长度 | 512B | 2KB | 8KB | 16KB | 32KB | 64KB | 128KB | 256KB |
|---|---|---|---|---|---|---|---|---|
| 耗时 | 27.7ms | 116.7ms | 755ms | 2.56s | 9.58s | >20s 超时 | >20s 超时 | >20s 超时 |

接近平方级增长，且「含 %20」与「纯文本」两条曲线耗时几乎相同，说明瓶颈不在 URL 解码层，而在对所有文本都跑的公共层。

### 白盒定位（熵计算，同一台容器）

| 文本长度 | 512B | 2KB | 8KB | 16KB | 32KB | 64KB |
|---|---|---|---|---|---|---|
| 原实现（逐字符 `mb_substr`） | 0.9ms | 12.1ms | 153ms | 589ms | 2404ms | 9245ms |
| 新实现（`preg_split` + `array_count_values`） | 0.21ms | 0.43ms | 1.20ms | 2.61ms | 4.68ms | 10.09ms |

熵值逐位一致（如 65536B 均为 4.4411），证明是纯算法复杂度问题，不是判定逻辑差异。

### 白盒定位（审计哈希链，同一台容器）

| 已有日志行数 | 100 | 1000 | 3000 | 8000 |
|---|---|---|---|---|
| 修复前 flush 1 条 | 0.9ms | 3.7ms | 10.5ms | 27.6ms |
| 修复后 flush 1 条 | 0.27ms | 0.39ms | 0.30ms | 0.44ms |

`php -S` / php-fpm 下每个请求都是独立的 `YslAudit` 实例，析构时 flush 1 条；
修复前单次成本与累计日志量成正比，累积就是 O(n²)，全局锁又让所有 worker 串行等待，
所以延迟随运行时间稳定上浮。修复后成本与日志量无关。白盒同时验证多次 flush 的
`prev_hash` 链连续，且删掉 `.last_hash` 后靠尾部读取仍能无损续链。

## 四、修复内容

| # | 文件 | 改动 |
|---|---|---|
| 1 | `core-src/YslNormalizer.php` | `calculateEntropy()` 改为一次性 `preg_split('//u')` + `array_count_values()`，O(n²) → O(n)；非法 UTF-8 时退化为字节级统计 |
| 2 | `ai-src/NaiveBayesClassifier.php` | `tokenize()` 增加 4096 字节「头 + 尾」特征窗口预算，内存钉死在几 MB，同时保留长尾载荷的判别能力 |
| 3 | `core-src/YslEngine.php` | `collectParamText()` 的 4000 字节截断改为**头尾各半**（预算不变，下游长度门槛无需改动），攻击夹在参数开头或结尾都能被硬规则看见 |
| 4 | `core-src/YslEngine.php` + `core-src/YslNormalizer.php` | 两处 `looksLikeDangerousPayload()` 同步补齐 SQL 恒真式、SSTI/EL 模板插值、CRLF 响应头注入三类通用攻击结构 |
| 5 | `core-src/YslAudit.php` | `flush()` 优先读由同一把锁保护的 `.last_hash`（O(1)）；`findLatestHash()` 回退路径改为只读最新日志末尾 64KB；`enforceTotalSizeLimit()` 从每请求挪到仅在轮转时执行 |

所有改动不改变放行逻辑与检出结果；性能修复只缩短临界区，哈希链语义与完整性不变；`WAF_BASE64_MASK_GUARD=0`、`WAF_TAUTOLOGY_GUARD=0`、`WAF_BYPASS_GUARD=0` 等回退开关保持有效。改后由私有构建流程重新加密对应 `core/` / `ai/` 文件，并用 `e2e_encrypted.sh` 验证字节码解密与判定一致。

## 六、已知边界与生产建议

这些不是失败项，但值得如实说明，避免数字被误读：

- **并发延迟与长稳漂移（已在代码层修复）**：首次复测曾观察到并发 64 P50 约 1.3s、长稳 P50 从 983ms 缓慢升到 1209ms，当时误判为 `php -S` + 磁盘 IO 退化并给出 tmpfs 建议。定位后确认根因是 `YslAudit::flush()` 每请求全量重扫历史日志找链末端 hash（O(n²)）叠加全局 `.audit.lock` 串行等待，见第四节第 5 项。修复后并发 64 P50 46.1ms、长稳 P50 23.2ms 且无漂移。把 `WAF_LOG_DIR` 指向 tmpfs 仍可进一步降低落盘开销，但不再是必需项；`php -S` 仅用于验收，生产仍推荐 php-fpm。
- **4MB 良性文本返回 413**：`buildPayloadText()` 会把已解析的参数值与原始 `php://input` 都计入，POST 表单下同一份内容被算两次，累计触及 8MB 的 `max_payload_bytes` 上限而保守拒绝。属设计内的 fail-closed 行为（不是放行、不是 5xx）；需要接收超大表单时可通过控制台 `config.body_max` 调高，或改用 `multipart`（body 不进入参数拼接）。
- **不可逆变异不判失败**：`b64` 全大写 / 全小写共 22 条返回 200，因为业务端无法还原该编码，不构成攻击路径。测试脚本明确区分「有效绕过」与「不可逆变异」，避免把无效变异算成漏放。
- **调试开关**：`WAF_DEBUG=1` 打开降级详情，`WAF_BASE64_MASK_GUARD=0` 单独回退指纹判定；`STRESS_STAGES` 可只跑单个阶段做定向复测。
